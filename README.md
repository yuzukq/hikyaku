# hikyaku（飛脚）

手持ちの USB キーボードの入力を受け取り、Bluetooth (BLE) で Mac に届ける無線中継器。
トラックパッドも内蔵し、分割キーボードの真ん中に置いて使うことを想定している。

```
[USB キーボード] --USB--> [hikyaku: ESP32-S3 + TM035035] --BLE HID--> [Mac]
                                   ↑
                             トラックパッド
```

## 構成

| 役割 | 部品 | メモ |
|---|---|---|
| マイコン | ESP32-S3 SuperMini（USB-C 1 ポート。ESP32-S3FH4R2 搭載。GPIO48 に RGB LED。AliExpress 品） | USB OTG でホストになれる + BLE。1チップで完結 |
| トラックパッド | Cirque Pinnacle TM035035（SPI 版） | 35mm 円形。J1 は 12 ピン 0.5mm FFC |
| USB 接続 | USB-C ⇔ USB-C ケーブル | ESP32-S3 ボードの USB-C をホストポートとして使う |
| 電源・ログ | 秋月 AE-CH9102F-TYPEC-BO（USB-シリアル変換） | USB-C にモバイルバッテリー（または PC）をつなぎ、+5V を S3 の 5V ピンへ（キーボードにも届く）。ログの取り出し口も兼ねる |

部品の詳細と手持ちの状況は [docs/hardware/parts.md](docs/hardware/parts.md)。

## 設計上の決定

- **マイコンは ESP32-S3**：nRF52840 は USB ホスト非対応のため不採用。ESP32-C3 も USB ホスト不可（Serial/JTAG のデバイス側のみ）で不採用。BLE 検証には使った
- **言語は Rust**（esp-hal + embassy + trouble）。USB ホストは esp-hal の OTG ホストドライバ + `embassy-usb-host`
- **一次電池は使わない**：USB キーボードへの 5V 給電を含めると全体で約 100mA 前後になり、コイン電池では動かず、乾電池では交換頻度が高い
- **ESP32-S3 の BLE は macOS で安定して動作した**（ボンディング保存・再起動後の自動再接続も確認済み）。nRF52840 は不要
- **HID レポートは詰め替える**：受け取ったキーボードのレポート記述子をそのまま流さず、固定の記述子（キーボード + コンシューマ + マウス）に変換する。キーボードごとに記述子が変わると macOS のペアリングキャッシュで不具合が出るため

## 既知の制約

- ボードの 5V ピンから外部給電すると、USB-C のポート経由でキーボードにも 5V が届く（動作確認済み）。ホスト動作中はここに外部から 5V を入れる
- 電池駆動ではボード単体では VBUS に 5V は出ない。モバイルバッテリー（5V）か昇圧モジュールが必要
- USB-C をホストに使うと USB CDC のシリアルログが使えない。デバッグは UART（USB-シリアル変換）で行う。キーボードを使わない間は、`usb-log` の版で S3 の USB-C から直接ログを読める（[docs/firmware.md](docs/firmware.md)）

## 現状

**v1 完成（2026-10-15）。** ユニバーサル基板に組んだ状態で、7skb（USB）→ S3（USB ホスト）→ BLE → Mac のパススルー（通常キー・メディアキー・マウス系、ボンディング保存つき）と、トラックパッド（相対モード、感度 2X、タップ = クリック）が同時に動作する。起動時は LED が赤（触らない）→ 緑（準備完了）。

モバイルバッテリーでの動作も確認済み。

残り: 静止中のぶれを抑えるフィルタ・電力まわりの最適化（次に着手）、長時間の自動オフの確認、CH9102F の受信の修理（ログ用）、ケース、PCB 化の検討、2 台切り替え（構想）。
