# ショートカットリング（Mac アプリ）仕様

**状態（2026-10-21）: ファームと通信は実装・実機確認済み。Mac アプリ（`mac/HikyakuRing`）も実装し、全機能を実機で確認済み（リングの表示・選択と実行・キャンセル・ノブモード・設定画面・⌃⌥R / URL での開閉）。**

丸いトラックパッドを活かして、Logi Options+ の Actions Ring のような**円形のショートカットリング**を Mac に出す。
Mac 側に hikyaku のフロントエンドとなるネイティブアプリ（Swift / SwiftUI）を作り、パッドに触れている位置をリング上に表示する。
割り当てるアクションは GUI で編集できる。見た目は Apple のデザインパターン（Human Interface Guidelines）に合わせる。

## 決めたこと

| 項目 | 決定 | 理由・補足 |
|---|---|---|
| パッドの読み方 | **普段は相対モード**（今のまま）、**リングを出している間だけ絶対座標モード** | 今の操作感（相対モード）を変えない。リングには指の位置が要る |
| 起動 | **F23 を短く押す**（7sPro の空きキーに割り当てる）か、**本体のボタンをダブルタップ**（2026-10-22 追加。`docs/firmware.md`）。もう一度 F23 か Esc で閉じる。開いて 5 秒触らなければ閉じる | 相対モードでは「指を止めて触れ続けている」が検出できない（止めるとパケットが来ない）ので、パッドの長押しでは起動できない |
| 配置 | **8 方向**（45° ずつ）にアイコン | Options+ と同じ |
| 選択と実行 | 縁付近に触れている位置の角度がリングの項目に対応し、**指を離した位置の項目を実行**。中心付近で離したら**キャンセル** | 離す瞬間の位置は乱れやすいので、離す直前（約 50ms 前）の位置で判定する |
| 連続値の項目（音量・明るさ・シーク） | 指を離すと、リングのウィンドウが**ノブ操作モード**に切り替わる。外周を右回り / 左回りで上げ下げ | 一定の角度ごと（例: 15°）に 1 段階 |
| ノブモードの抜け方 | **中心をタップ** | |
| 普通の項目 | 任意のキーの組み合わせを割り当てられる | |
| Mac アプリが接続していないとき | F23 は何もしない（そのまま Mac に送るかは要検討） | Windows など、アプリのないホストで誤動作させない |

## 構成と分担

```
[7sPro] --F23--> [hikyaku] --BLE: HID（キー・マウス）--------------------> [Mac]
                     |      --BLE: 独自サービス（リングの状態・位置）--> [hikyaku アプリ]
                     |      <-BLE: 独自サービス（終了・キー送出など）--- [hikyaku アプリ]
                [トラックパッド: 普段は相対 / リング中は絶対座標]
```

### ファーム（hikyaku）

- F23 を検出したら（Mac には送らない）、アプリが独自サービスを購読しているときだけ**リングモード**に入る。
- リングモードの間:
  - パッドを**絶対座標モード**に切り替える（FeedConfig1 を書き換える。キャリブレーションはやり直さない想定。要実験）。
  - マウスの移動・タップのレポートを止める（カーソルを動かさない）。
  - 指の状態を約 100Hz で独自サービスに notify する: **角度**（0〜360°、パッドの 90° の取り付けを補正済み）、**中心からの距離**（0〜1）、**触れているか**。
  - 位置の正規化（パッドの中心と半径）は、実機の座標の範囲から決める。Y の bit11 は 11 ビットにマスクする（タグ `absolute-mode-last` のコードを参照）。
- アプリから「終了」を受け取るか、F23 / Esc / 時間切れで、相対モードに戻す。
- 絶対座標の読み方は、タグ `absolute-mode-last` に残っているコード（`read_absolute`・`parse_absolute`）を戻して使う。

### Mac アプリ（Swift / SwiftUI。Mac 上で開発）

- CoreBluetooth で、すでに接続済みの hikyaku（`retrieveConnectedPeripherals(withServices:)`）の独自サービスを購読する。
- リングの表示（カーソル位置付近に出すオーバーレイ）、触れている位置のフィードバック、項目の選択（境目でちらつかないようヒステリシスを持たせる）、
  指を離したときの実行、ノブモードの回転の計算と表示、設定画面（アクションの割り当て）。
- 調整値（境目の幅、キャンセル範囲、ノブの 1 段階の角度など）はアプリ側で持つ（ファームの書き換えなしで試せる）。

## アクションの実現方法

| アクション | 方法 | 補足 |
|---|---|---|
| 音量 | hikyaku から HID のメディアキー（Consumer の Volume Up / Down）を送る | BLE の記述子に入っている。Mac 標準の音量表示も出る |
| 画面の明るさ | 内蔵ディスプレイは HID の明るさキー | 外部モニタは DDC/CI が必要で難しい（後回し） |
| シーク | Spotify・ミュージックは AppleScript（`player position`） | どのアプリでも効く方法（MediaRemote）は、macOS 15.4 以降、一般のアプリから使えない。アプリごとに対応する |
| 任意のキーの組み合わせ | アプリから hikyaku に頼んで、本物のキーボード入力として送る（許可が要らない）。または CGEvent（アクセシビリティの許可が要る） | 前者を第一候補にする |

## 確認済みのこと（2026-10-21）

- **macOS は、HID として接続中の hikyaku の独自サービスに、アプリからアクセスさせる**（`mac/RingProbe` で確認。
  `retrieveConnectedPeripherals(withServices: [ring サービス])` で見つかる。HID の UUID 0x1812 では見つからない）。
- 相対モード ↔ 絶対座標モードの切り替えは、キャリブレーションをやり直さずに動く。閉じた後のカーソル操作も元どおり。
- 位置のイベントは約 70/秒、取りこぼしなし。8 方向の判定、離した位置での実行・キャンセルが狙いどおり。
- パッドの円: X 260〜1719、Y 191〜1398（縁をなぞった範囲）→ 中心 (989, 794)、半径 (729, 603)。向きは XY 入れ替え + 上下反転
  （`hikyaku_pointer::ring::Geometry::DEFAULT`。カーソルと違い、左右は反転しない）。

## 通信の取り決め（確定）

独自サービス `6b9a0010-6f1e-4b8e-9d57-7f0d0a5b0001`。実装: `crates/hikyaku-pointer/src/ring.rs`（形式とテスト）、`firmware/hikyaku-s3/src/bin/main.rs`（`RingService`・`ring_ctrl`）。

### state（`6b9a0011-…`、read / notify、12 バイト固定）: hikyaku → アプリ

| バイト | 内容 |
|---|---|
| 0 | 種類: 1 = 開いた、2 = 閉じた、3 = 位置 |
| 1 | bit0 = 触れている |
| 2〜3 | 角度（0.01° 単位、リトルエンディアン）。0° = 上、時計回り（画面上の向き） |
| 4〜5 | 中心からの距離（パッドの縁 ≒ 1000。外へはみ出すと 1000 を超える） |
| 6〜7, 8〜9 | パッドの生の X, Y（調整用） |
| 10 | Z（接触の強さ。離す直前は小さくなる） |
| 11 | 通し番号（取りこぼしの確認用） |

### ctrl（`6b9a0012-…`、write / write without response）: アプリ → hikyaku

| バイト列 | 意味 |
|---|---|
| `00` | HELLO。接続したら最初に送る。これを受け取るまで F23 でリングは開かない（接続が切れるとリセット） |
| `01` | 閉じる（実行後・キャンセル・ノブモードの終了） |
| `02` | 開く（アプリのボタンや試験用。F23 と同じ） |
| `10 mm kk` | キーの組み合わせを押して離す。mm = 修飾キー（bit0 Ctrl, 1 Shift, 2 Option, 3 Command。4〜7 は右側）、kk = HID の Usage ID |
| `11 lo hi` | メディアキーを押して離す（Consumer の Usage、16 ビット）。音量 +0x00E9 / −0x00EA、ミュート 0x00E2、明るさ +0x006F / −0x0070、再生 0x00CD、次 0x00B5、前 0x00B6 |

`10`・`11` は hikyaku から**本物のキーボード入力**として届くので、アプリにアクセシビリティの許可は要らない。

### ファームの動き

- 開く: F23 を押す（Mac には送らない）か `02`。アプリが `00` を送っていないと開かない。
- 開いている間: パッドは絶対座標モード、カーソルは動かない。位置のイベントを約 70/秒で送る。
- 閉じる: `01`、F23、Esc（リング中だけ。Mac には送らない）、5 秒間触れない、切断。閉じると相対モードに戻る。
- **指を離すと、「触れていない」イベント（バイト 1 の bit0 = 0）が 5 回続けて来る**（パッドの ZIdle = 5）。
  アプリは「触れている → 触れていない」に変わった**最初の 1 回だけ**を「離した」として扱う。
- 離す直前のイベントは Z が小さく、位置もぶれやすい。項目の判定は**離す約 50ms 前の位置**で行う。

## Mac アプリ

実装: `mac/HikyakuRing`（SwiftPM。Xcode のプロジェクトは使わない）。

```sh
mac/HikyakuRing/build.sh --open   # build/HikyakuRing.app を作って起動する（メニューバーに常駐）
cd mac/HikyakuRing && swift test  # 通信の形式・選択・ノブの計算のテスト
```

- Bluetooth の許可に Info.plist が要るので、`swift run` ではなく `.app` にまとめて起動する。
  署名はキーチェーンの「Apple Development」の証明書（なければアドホック。その場合はビルドのたびに許可を聞き直されることがある）。
- 構成: `RingCore`（形式 `Protocol.swift`、状態遷移 `RingMachine.swift`、設定 `Config.swift`、キーの対応 `Keys.swift`）と、
  アプリ（BLE `RingLink.swift`、つなぎ役 `RingController.swift`、表示 `OverlayPanel.swift`・`RingOverlayView.swift`、
  実行 `Actions.swift`、設定画面 `SettingsView.swift`）。
- 7sPro なしで開く: **⌃⌥R**（全体のホットキー。開いていれば閉じる）か `open -g hikyaku-ring://open`（`close`・`toggle` も）。
  どちらもアプリから `02` / `01` を送るだけで、F23 と同じ動き。Mac で押した F23 は hikyaku に届かない
  （ファームが F23 を見るのは 7sPro からの USB 入力だけ。Mac → hikyaku の HID は LED の出力レポートしかない）。
- ログ: `log stream --predicate 'subsystem == "dev.hikyaku.ring"' --info`
- 設定: `~/Library/Application Support/HikyakuRing/config.json`（なければ標準の 8 項目）。
- キーの記録: ⌘Space のように Mac が先に取るキーは記録できないので、キーだけ記録して修飾キーのボタンで足す。

以下は作るときの仕様（実装はこれに沿っている）。

### 作るもの

- メニューバー常駐のアプリ（`MenuBarExtra`）。起動時に接続済みの hikyaku を探して ring を購読し、`00` を送る。切断されたら再接続を待つ。
- **リングのオーバーレイ**: 「開いた」でマウスカーソルの位置付近に表示する。フォーカスを奪わない透明なパネル
  （`NSPanel` の nonactivating、`.floating` 以上のレベル、全デスクトップに表示）。
  - 8 方向にアイコン（SF Symbols）と名前。触れている位置の方向の項目を強調し、指の位置の点を表示する。
  - 中心付近（距離 < 350。調整可）はキャンセル範囲として表示を変える。境目でちらつかないよう、項目の切り替えに数度のヒステリシスを持たせる。
  - 離したら: 項目が「普通の項目」なら実行して `01` を送り、閉じる。キャンセル範囲なら `01` で閉じる。
    「連続値の項目」ならノブモードへ。
- **ノブモード**: ウィンドウをノブの表示に切り替える（項目名と現在値・円弧）。外周を右回りで増、左回りで減。
  角度の変化を積算して、一定の角度（初期値 15°、調整可）ごとに 1 段階。中心付近（距離 < 350）を短くタップ（触れて 250ms 以内に離し、
  ほぼ動かない）したら抜けて `01` を送る。0°/360° をまたぐ角度の差に注意する。
- **アクション**:
  - キーの組み合わせ → `10 mm kk`（hikyaku から送る）
  - 音量・明るさ（連続値）→ `11` の Volume Up/Down・Brightness Up/Down を 1 段階ごとに送る
  - シーク（連続値）→ Spotify・ミュージックは AppleScript の `player position` を増減（1 段階 = 例: 5 秒）。対象アプリが動いていなければ何もしない
  - 再生・次・前 → `11`
- **設定画面**（SwiftUI の `Settings`）: 8 か所それぞれに、名前・アイコン・アクションの種類と内容を割り当てる。キーの組み合わせは押して記録できると良い。
  設定は `~/Library/Application Support/` に JSON で保存する。
- 見た目は Apple の Human Interface Guidelines（vibrancy の素材、SF Symbols、標準のコントロール）。

### 注意

- Bluetooth の利用には Info.plist の `NSBluetoothAlwaysUsageDescription` が要る（Xcode のプロジェクトで作るのが楽）。
- hikyaku は同時に 1 台としかつながらない。Linux の確認クライアント（`tools/ring/ring.sh`）でペアリングした PC が近くにあると、そちらが接続を取ることがある
  （PC で `bluetoothctl disconnect FF:E4:05:1A:8F:FF`）。
- macOS は hikyaku の GATT を覚えている。サービスを足したり変えたりしたファームの後は、Mac で hikyaku を削除して再ペアリングが要ることがある。
