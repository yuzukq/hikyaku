# 設計メモ: 2 台のマシンの切り替え（検討中・未実装）

要望: Mac と Windows を同時に使うので、キーボード（とトラックパッド）の入力先を切り替えたい。
例: Alt+Ctrl+Win+Shift+Enter+1 で BLE1（Mac）、…+2 で BLE2（Windows）。

## 切り替えキー

`Ctrl+Alt+Shift+Gui（左右どちらでも）+ Enter + 1/2` は、ブートレポート上は「修飾キー 4 つ + 通常キー 2 つ」で、6KRO に収まる。
S3 が USB から読んだレポートの時点で検出できる。検出したら:

1. 切り替えのコードはどちらにも転送しない（Enter や 1 が打鍵されないように）
2. 切り替え前のホストへ「全キー解放」を送る（押しっぱなしを残さない）
3. 全キーが離されるまで、新しいホストへの転送を抑える

ほかに、7skb の QMK 側で専用キーコード（F23/F24 など使われないキー）を割り当てる方法もある。どちらも同じ仕組みで受けられる。

## 方式

| | A. 同時接続 + 経路切り替え（推奨・要検証） | B. 1 台ずつ接続（Easy-Switch 型） |
|---|---|---|
| 仕組み | 両方のホストと BLE 接続したままにして、アクティブな方にだけレポートを送る | アクティブなホストにだけ接続する。切り替えで切断→別ホストへ再接続 |
| 切り替えの速さ | ほぼ即時 | 1〜3 秒 |
| 非アクティブ側の見え方 | 接続されたまま（キーが来ないだけ） | 切断表示になる |
| 実装 | 複数接続、接続ごとの購読管理、ボンドと「スロット」の対応づけ | アドバタイズの宛先制御（アクセプトリスト）または名前で区別 |
| 不確実な点 | 現在の BLE スタック設定（接続数 1）で ESP32-S3 が 2 接続できるか、接続中のアドバタイズができるか | アドバタイズの切り替え時の再接続の安定性（OS ごとに差） |

どちらも、ボンディング保存を「スロット番号つき」に拡張する（スロット 1 = BLE1、2 = BLE2）。

## 名前（hikyaku-BLE1 / BLE2）

アドレスを 1 つのままにして、**ペアリングモードのアドバタイズ名**だけをスロットごとに変える（`hikyaku-BLE1`, `hikyaku-BLE2`）。
ホスト OS は最初に見た名前を覚えるので、Mac では BLE1、Windows では BLE2 と表示される。

## 状態の見える化

どのホストが有効かは画面を見ないと分からないので、S3 のオンボード LED で示す:
切り替え時にスロット番号の回数だけ点滅、ペアリングモード中は速く点滅、など。

## 気をつけること

- **Windows の HID over GATT:** Device Information サービス（PnP ID）が無いとペアリングや接続に失敗することがある、と知られている。現状は未実装。実機で確認して、必要なら追加する。
- **トラックパッドのマウスレポートも、同じくアクティブなホストへだけ送る。**
- ボンディングの保存形式を変える（スロット番号の追加）。既存の保存データの扱いを決める。
- Linux の PC を 2 台目のホストとして使えば、Windows が無くても複数接続のテストはできる（Mac + Linux PC）。

## 提案する進め方

1. A が成立するかの検証（2 接続・接続中のアドバタイズ。Mac + Linux PC）
2. ダメなら B
3. 切り替えキーの検出、ボンディングのスロット化、LED 表示
4. Windows で実機確認（Device Information サービスの要否）
